
# Stratum Pipeline — Stage 01: Extract Android JAR

## Overview & Architectural Context

Stage 01 serves as the foundational data source provider for the Stratum pipeline. It reads the configuration emitted by **Stage 00 (`00_setup`)**, locates the platform-specific `android.jar` stub SDK file, and performs a clean, filtered extraction of all compiled Java bytecode (`.class`) files into a flat on-disk directory mirror.

In the Stratum architecture:
- Downstream inspection (**Stage 02**) and reflection parsing (**Stage 03** via `javap`) require individual class files indexed directly on a filesystem classpath rather than inside an opaque ZIP container.
- Stage 01 acts as a deterministic, cached mirror: unnecessary files (like `META-INF/` manifests, signing keys, and resource bundles) are pruned at extraction time so subsequent stages only process pure Java type definitions.

---

## Quick Start / CLI Demo

```bash
# Standard extraction using setup report
python 01_extract/main.py \
    --setup "00_setup/output/setup_report.json" \
    --output "01_extract/output/"

# Force re-extraction (bypasses cache when testing a new SDK or API level)
python 01_extract/main.py \
    --setup "00_setup/output/setup_report.json" \
    --output "01_extract/output/" \
    --force
```

---

## Command-Line Arguments

| Flag | Type | Required | Description |
|---|---|:---:|---|
| `--setup` | `Path` | **Yes** | Absolute or relative path to `setup_report.json` generated by Stage 00. Provides the verified paths to `android.jar` and the Android API level. |
| `--output` | `Path` | **Yes** | Destination directory where the extracted `.class` hierarchy and `extract_summary.json` will be written. |
| `--force` | `Flag` | No | Overrides cache validation. Forces unpacking even if `extract_summary.json` already exists in the destination. |

---

## Execution Workflow

1. **Setup Validation**: Reads `setup_report.json` to obtain `jar_path` and `android_api`. If the setup report or the specified `android.jar` does not exist on disk, the script exits immediately with code `1`.
2. **Cache Verification**: Checks if `01_extract/output/extract_summary.json` exists:
   - If present and `--force` is **not** specified, it logs a `[CACHE HIT]` notice and exits cleanly (`code 0`) without redundant disk writes.
   - If missing or `--force` is passed, extraction proceeds.
3. **Selective Extraction**:
   - Opens `android.jar` using Python's streaming `zipfile.ZipFile`.
   - Filters out non-class entries and metadata (anything in `META-INF/`).
   - Unpacks each valid class into `--output`, preserving folder hierarchies (e.g., `android/widget/Button.class`).
   - Tracks per-package class densities and progress in increments of 2,000 files.
4. **Summary Aggregation**:
   - Compiles package counts, sorts them descending by frequency, and serializes the operational metrics into `extract_summary.json`.

## Output Schema: `extract_summary.json`

```json
{
  "android_version": "35",
  "total_classes": 14823,
  "extraction_time_seconds": 3.42,
  "packages": {
    "android.view": 412,
    "android.content": 387,
    "android.widget": 341,
    "android.graphics": 298,
    "android.os": 276
  },
  "timestamp": "2026-03-26T22:10:05.123456"
}
```

### JSON Fields

- `android_version` (`string`): The target Android API level recorded by Stage 00.
- `total_classes` (`int`): Total count of non-metadata `.class` files extracted.
- `extraction_time_seconds` (`float`): Total wall-clock time spent unzipping.
- `packages` (`object`): Dictionary of package names to class counts, sorted largest-first.
- `timestamp` (`string`): ISO-8601 execution timestamp.

## Troubleshooting & Exit Codes

| Exit Code | Reason | Resolution |
|:---:|---|---|
| `0` | Successful extraction or cache hit. | Proceed to **Stage 02 (`02_inspect`)**. |
| `1` | `setup_report.json` missing or corrupt. | Run `python 00_setup/main.py ...` first. |
| `1` | Target `android.jar` not found at recorded path. | Verify your Android SDK platform installation (`platforms/android-XX/android.jar`). |
